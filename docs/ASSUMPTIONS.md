# افتراضات الديمو — Furniture Commerce OS

كل ما يلي **افتراضات هندسية مؤقتة** لبناء ديمو توضيحي. ليست قرارات العائلة النهائية ولا أسعار الورشتين الحقيقيتين.

## حقائق معروفة (من سياق المشروع)

- مشروع عائلي به ورشتان للأثاث.
- منتجات جاهزة + طلبات تفصيل حسب الطلب.
- البيع الحالي عبر وسائل التواصل (واتساب / فيسبوك / إنستجرام…).
- الجمهور الأولي: أفراد وعملاء محتملون.
- الميزانية محدودة → ديمو static بدون Backend مدفوع.

## بيانات مجهولة (لم تُخترع كحقائق)

| الموضوع | الحالة في الديمو |
|---------|------------------|
| أنواع المنتجات والمقاسات والخامات الفعلية | قوائم وأوصاف تجريبية قابلة للتعديل |
| الفرق التشغيلي بين جاهز وتفصيل | حقل `kind` + مسار طلب منفصل |
| تسجيل العميل والطلب والعرض | نموذج استفسار + حالات طلب + نسخ عروض أسعار |
| التسليم والتوصيل | حالة «جاهز للتسليم» / «تم التسليم» فقط — بلا منطق شحن |
| الدفع الحقيقي | دفعات تجريبية محلية فقط |
| الصلاحيات والأدوار | لوحة عامة تقنيًا — ليست نظام صلاحيات |
| التكلفة والربح | غير مسجّلة — المؤشرات قيمة عرض ≠ محصّل ≠ ربح |

## قواعد الحساب التجريبية

- العملة: جنيه مصري (أرقام صحيحة).
- إجمالي العرض = مجموع البنود − خصم + رسوم إضافية (≥ 0).
- الرصيد المتبقي = max(0, الإجمالي − مجموع الدفعات).
- حالات الدفع: غير مدفوع / جزئي / مدفوع بالكامل.

## ما يحتاج تأكيد العائلة

1. الأسعار والخامات والمقاسات الحقيقية.
2. تدفق العربون والتسليم والإلغاء.
3. أدوار الأفراد (من يرد / من يسعّر / من يسلّم).
4. قنوات التواصل الرسمية وأرقام الاتصال.
5. هل يُستبدل الديمو بنظام Backend حقيقي أم يبقى أداة عرض.
